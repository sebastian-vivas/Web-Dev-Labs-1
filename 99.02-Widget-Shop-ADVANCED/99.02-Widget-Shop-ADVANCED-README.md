### **\*\*\*\***\*\***\*\*\*\***\_\_\_**\*\*\*\***\*\***\*\*\*\***-

This is the same shop as the BEGINNER track (project 99.01), but you build it the way a working developer would. The HTML page has **no products in it**. Your JavaScript renders everything from data.

When you are done, your shop will:

- Be **data-driven**: products come from an array of objects made by a factory function
- Keep all money in **integer cents**, so there is no floating-point drift
- Have a **pricing engine** of small, testable functions: bulk-quantity tiers, coupons with rules (minimum spend, weekends only), shipping, tax
- Render the catalog, the cart, and the summary from one `state` object
- Handle every button with **one delegated event listener**
- Validate the checkout form and show **all** the errors at once
- Store orders as **snapshots** and show session stats
- Have keyboard shortcuts, a saved theme, and a deterministic "deal of the day"

### How to read this README

You build the shop one step at a time. The steps describe **what to build, not the code**: you write the code. Every step is laid out the same way:

| Part of a step | What it tells you |
| --- | --- |
| The numbered sentence | The one thing to build. The same sentence is the comment in your PROG.js file |
| **What to do** | The exact names, parameters, return values, and rules. **Use the names exactly as written**: later steps depend on them |
| **Check it in the console** | Lines to run in the browser console, and the answer each one must give. If an answer is different, fix your code before moving on |
| **What you should see** | What changes on the page (or that nothing does yet) |
| **Good to know** | Background, and the reason the step is written this way |
| **Hint** | Only if you are stuck. Try without it first |

Some steps say **"Add this to the function you just wrote."** That means: don't start a new function. Find the one from the earlier step and add to it.

If you are badly stuck, the `checkpoints/` folder has the finished code at the end of each part, and the FINAL file is a complete reference solution.

### Four rules for this track

1. **Data, then logic, then display.** Parts 1 and 2 never touch the page. You can test them entirely in the console.
2. **Money is integers.** `1999` means $19.99. Only `formatMoney()` turns cents into a string.
3. **Functions return; they don't reach out.** A function that calculates something returns a value or a result object like `{ ok: true, message: "..." }`. Only the render functions write to the page.
4. **One source of truth.** The `state` object is the only place the cart, coupon, and shipping choice live. The page is redrawn from it.

### Page map (the ids and classes in the HTML)

Your code finds things on the page with `document.getElementById("...")`. Everything inside `#catalog` and `#cart-items` is **empty**: you render it.

| Where | Ids |
| --- | --- |
| Header | `shop-name`, `greeting`, `today-date`, `deal-banner` |
| Containers you fill | `catalog`, `cart-items` |
| Price summary | `sum-subtotal`, `sum-discount`, `sum-tax`, `sum-shipping`, `sum-total` |
| Checkout form | `checkout-form`, `customer-name`, `customer-email`, `coupon-code`, `coupon-note` (a line under the coupon box), `shipping-menu`, `order-btn` |
| Feedback | `errors` (a `<ul>`), `message`, `receipt`, `history` |

The Apply button is `<button type="button" data-action="apply">`. The CSS has these classes ready for you: `item`, `sticker`, `tags`, `stock` (also `stock low`, `stock out`), `tape-line`, `note`, `qty-controls`, `plain`, and `message` (also `message ok`, `message error`).

**What to do:**

**Why it works:** All money in this track is whole **cents**. `10000` means $100.00. That is rule 2.

2. Create `formatMoney(cents)`, which returns an amount in cents as a dollar string like `"$19.99"`.

**What to do:**

- Name: `formatMoney`. One parameter: `cents` (a whole number).
- It **returns** a string: a `$`, then the amount in dollars with exactly two decimal places.

> **Hint:** Divide by 100, then use `toFixed(2)`.

5. Add a `getPrice()` method to the object that `makeProduct` returns.

**What to do:**

**Add this to the function you just wrote** (`makeProduct`), as a new property of the object it returns.
- Name: `getPrice`. No parameters. Write it as a function expression, `getPrice: function () { ... }`, so that `this` is the product.
- It **returns** the product's current price in cents.
- When `this.onDeal` is `false`, that is `this.price`.
- When `this.onDeal` is `true`, it is `this.price` reduced by `DEAL_PCT` percent, **rounded to the nearest whole cent**.
- Use a ternary.

> **Hint:** The deal price is `Math.round((this.price * (100 - DEAL_PCT)) / 100)`. A method is just a function stored in a property.

**Check it in the console** (type these in the console and press Enter):

```js

```

**What you should see:** Nothing changes on the page. The console prints `1999`, then `1599`. The last line turns the deal off again.

**Why it works:** Inside a method, `this` is the object the method was called on. `products[0].getPrice()` has `this === products[0]`.

6. Add `getAvailable(inCart)` and `isLowStock(inCart)` methods to the same object.

- `isLowStock(inCart)` **returns** `true` when 1 or 2 are available, and `false` otherwise (0 available is not "low", it's "out"). It must call `this.getAvailable(inCart)` instead of repeating the subtraction.

**Check it in the console** (type these in the console and press Enter):

**Why it works:** A default parameter (`inCart = 0`) is used when the caller leaves the argument out. That's why `products[2].getAvailable()` works with no argument.

## Part 2: The pricing engine

*Suggested time: 11:00-11:55 (55 min)*

The brain of the shop. Everything in this part is a function that takes data in and returns data out: no DOM, no `document`. That makes it easy to test and impossible to break by changing the page.

**You will build:** `getTierPct`, `getLineTotal`, a `createCart` factory, `validateCoupon`, `getShippingCost`, and `calcTotals`.

**Key ideas:** pure functions, result objects (`{ ok, message }`), guard clauses, early returns, default parameters for testability.

11. Create `getTierPct(qty)`, which returns the bulk-discount percent for a quantity.

**What to do:**

- Name: `getTierPct`. One parameter: `qty`.
- It **returns** the `pctOff` of the **highest** tier in `TIERS` whose `minQty` the quantity has reached.
- Check the highest tier first, and use early `return`s.

> **Hint:** Three `if`s, highest tier first: `if (qty >= TIERS[2].minQty) return TIERS[2].pctOff;`. (Stretch, once you know loops: make it work for any number of tiers.)

**Check it in the console** (type these in the console and press Enter):

```js
console.log(getTierPct(1), getTierPct(2), getTierPct(3), getTierPct(4)); // 0 0 5 5
console.log(getTierPct(5), getTierPct(50)); // 10 10
```

**What you should see:** Nothing changes on the page. The console prints `0 0 5 5`, then `10 10`.

12. Create `getLineTotal(product, qty)`, which returns one cart line's total in cents, with the deal price and bulk discount applied.

**What to do:**

- Name: `getLineTotal`. Two parameters: `product` (a product object) and `qty`.
- Start with `product.getPrice() * qty`, which already includes the deal price.
- Then take off `getTierPct(qty)` percent.
- **Round once, at the very end**, to a whole number of cents, and return it.

> **Hint:** `Math.round(gross * (100 - pct) / 100)` stays in whole numbers until the single rounding.

**Check it in the console** (type these in the console and press Enter):

```js
console.log(getLineTotal(products[0], 1)); // 1999
console.log(getLineTotal(products[0], 3)); // 5697
console.log(getLineTotal(products[1], 5)); // 15525
```

**What you should see:** Nothing changes on the page. The console prints `1999`, `5697`, and `15525`.

**Why it works:** `1999 * 3 = 5997`, minus 5% is `5697.15`, which rounds to `5697`. Rounding at the end of the calculation (not in the middle) keeps the result as exact as possible.

13. Create the factory `createCart()`, which returns a cart object with an `items` object and a `getQty(id)` method.

**What to do:**

- Name: `createCart`. No parameters. It **returns** an object.
- The object has a property `items`, which starts as an empty object `{}`. It will look like `{ widget: 2, gizmo: 1 }`: product ids and quantities.
- It has a method `getQty(id)` (a function expression that uses `this`). It **returns** the quantity of that id in `items`, or `0` if it isn't there. Don't use an `if`: use a falsey value and `||`.

**Check it in the console** (type these in the console and press Enter):

```js
console.log(createCart().getQty("widget")); // 0
```

**What you should see:** Nothing changes on the page. The console prints `0`.

**Why it works:** `this.items[id]` is `undefined` when the id isn't in the cart. `undefined` is falsey, so `undefined || 0` gives `0`.

14. Add a `change(id, delta)` method to the cart that adds `delta` to a product's quantity, and returns a `{ ok, message }` result object.

**What to do:**

**Add this to `createCart`**, below `getQty`. Name: `change`. Two parameters: `id` and `delta` (a positive number adds, a negative number removes).

It **returns** a result object `{ ok: boolean, message: string }`. Work through these rules **in this order**, with early `return`s:

1. No product has that id (`findProduct(id)` is `undefined`): `{ ok: false, message: "Unknown product." }`
2. `delta` is not a whole number (`Number.isInteger(delta)` is `false`): `{ ok: false, message: "Quantity must be a whole number." }`
3. Work out `wanted`: the current quantity plus `delta`.
4. `wanted` is more than the product's `stock`: `{ ok: false, message: "Only 5 Wonder Widget in stock (you have 3 in your cart)." }` (use the real stock, name, and current quantity)
5. `wanted` is 0 or less: remove the id from `items` with `delete`, and return `{ ok: true, message: "Removed Wonder Widget." }`
6. Otherwise, store `wanted` in `items`, and return `{ ok: true, message: "Wonder Widget × 3 in cart." }` (use the name and the new quantity)

**A failed call must not change the cart.**

**Check it in the console** (type these in the console and press Enter):

```js
var c = createCart();
console.log(c.change("widget", 3)); // { ok: true, message: "Wonder Widget × 3 in cart." }
console.log(c.change("widget", 5)); // { ok: false, message: "Only 5 Wonder Widget in stock (you have 3 in your cart)." }
console.log(c.change("widget", 1.5).ok, c.change("nope", 1).ok); // false false
console.log(c.getQty("widget")); // 3
console.log(c.change("widget", -3).message, c.getQty("widget")); // Removed Wonder Widget. 0
```

**What you should see:** Nothing changes on the page. The console prints the five lines shown. The failed calls leave the quantity at `3`.

**Why it works:** Returning `{ ok, message }` (instead of throwing errors or writing to the page) lets any caller decide what to do with the result. The page code later shows the message. Other code can just check `ok`.

16. Create `validateCoupon(code, subtotal, date = new Date())`, which returns `{ ok, pct, message }` for a coupon code.

**What to do:**

- Name: `validateCoupon`. Three parameters: `code` (text), `subtotal` (cents), and `date`, which **defaults to `new Date()`**.
- **Returns** `{ ok: boolean, pct: number, message: string }`.
- Clean the code first: `trim()` it and make it UPPERCASE. Call the result `key`.
- Then check these in order, with early `return`s:

| If | Return |
| --- | --- |
| `key` is empty (no coupon is fine) | `{ ok: true, pct: 0, message: "" }` |
| `COUPONS[key]` doesn't exist | `{ ok: false, pct: 0, message: "FOO is not a valid coupon." }` (with the key) |
| the coupon has a `minSubtotal` and `subtotal` is lower | `{ ok: false, pct: 0, message: "BIGSPENDER needs a subtotal of at least $150.00." }` (use `formatMoney`) |
| the coupon has `days` and `date.getDay()` isn't in them | `{ ok: false, pct: 0, message: "WEEKEND is only valid on weekends." }` |
| otherwise | `{ ok: true, pct: coupon.pct, message: "SAVE10: 10% off" }` (the key, a colon and space, then the coupon's `note`) |

- An invalid coupon always has `pct: 0`.

> **Hint:** A coupon without a `minSubtotal` has `undefined` there, which is falsey, so `if (coupon.minSubtotal && ...)` skips the rule. `coupon.days.includes(date.getDay())` checks the weekday list.

**Check it in the console** (type these in the console and press Enter):

```js
var friday = new Date(2026, 9, 16);
var saturday = new Date(2026, 9, 17);
console.log(validateCoupon("  ", 5000, friday)); // { ok: true, pct: 0, message: "" }
console.log(validateCoupon("save10", 5000, friday)); // { ok: true, pct: 10, message: "SAVE10: 10% off" }
console.log(validateCoupon("foo", 5000, friday).message); // FOO is not a valid coupon.
console.log(validateCoupon("bigspender", 5000, friday).message); // BIGSPENDER needs a subtotal of at least $150.00.
console.log(validateCoupon("weekend", 5000, friday).message); // WEEKEND is only valid on weekends.
console.log(validateCoupon("weekend", 5000, saturday).pct); // 15
```

**What you should see:** Nothing changes on the page. The console prints the six lines shown.

**Why it works:** The `date` parameter has a **default value** of right now. Why? So you can test "what happens on a Saturday?" by passing a date, instead of waiting for the weekend.

17. Create `getShippingCost(method, subtotal)`, which returns the shipping price in cents.

**What you should see:** Nothing changes on the page. The console prints `1499 599`, then `0 0`, then `0`.

18. Create `calcTotals(cart, couponCode, shipMethod, date = new Date())`, which returns every amount the page and the receipt need, in cents.

**What to do:**

- Name: `calcTotals`. Four parameters: `cart`, `couponCode`, `shipMethod`, and `date` (defaults to `new Date()`).
- **Returns an object** with these eight properties:

| Property | Value |
| --- | --- |
| `lines` | the array from `cart.getLines()` |
| `subtotal` | the sum of the lines' `lineTotal` |
| `discount` | the coupon's `pct` percent of the subtotal, rounded to a whole cent. `0` if the coupon is invalid |
| `tax` | `TAX_RATE` times (subtotal minus discount), rounded to a whole cent |
| `shipping` | from `getShippingCost(shipMethod, subtotal)` |
| `total` | `subtotal - discount + tax + shipping` |
| `couponOk` | the `ok` from `validateCoupon` |
| `couponMessage` | the `message` from `validateCoupon` |

- Pass `subtotal` and `date` to `validateCoupon`.
- Round `discount` and `tax` at the moment you compute them, so every amount is a whole number of cents and `total` is exact.

> **Hint:** Add up the subtotal with `forEach` and a running total (or `reduce`, if you know it).

**Check it in the console** (type these in the console and press Enter):

```js
var friday = new Date(2026, 9, 16);
var cc = createCart();
cc.change("widget", 3);
```

31. Create `escapeHTML(text)`, which makes user-typed text safe to put into `innerHTML`.

**What to do:**

- Name: `escapeHTML`. One parameter: `text`. It **returns** the text with `&`, `<`, `>`, and `"` replaced by `&amp;`, `&lt;`, `&gt;`, and `&quot;`.
- Do `&` **first**, or you will escape the `&` in the others.
- You will use `string.replace()` with a regular expression. The `g` flag means "every one," not just the first.
- Type the code below. You will call this function on every piece of user text in this part.

```js
function escapeHTML(text) {
  return text
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g, "&quot;");
}
```

**Check it in the console** (type these in the console and press Enter):

```js
console.log(escapeHTML("<b>Sam</b>")); // &lt;b&gt;Sam&lt;/b&gt;
console.log(escapeHTML('a & "b"')); // a &amp; &quot;b&quot;
```

**What you should see:** Nothing changes on the page. The console prints the two escaped strings.

**Why it works:** Anything the customer types (their name!) can contain HTML. If you put `<img src=x onerror=alert(1)>` into `innerHTML` unescaped, it **runs**. This is called an XSS (cross-site scripting) attack. Turning those four characters into harmless text stops it.

The details that make an app feel finished. This is the part where the things you learned on Days 2 and 5 come back: the `Date` object, `classList`, and keyboard events.

**You will build:** the greeting and date, a theme that is remembered between visits, and keyboard shortcuts.

**Key ideas:** `Date` and `toLocaleDateString`, `classList.toggle`, `try`/`catch` around `localStorage`, a lookup table of functions, guards inside event listeners, the `preventDefault()` gotcha with `keydown`.

40. Create `getGreeting(hour)` and `getDateString(date)`.

- `getDateString(date)`: one parameter, a `Date`. **Returns** a long-form date like `"Friday, October 16, 2026"`, using `date.toLocaleDateString("en-US", { weekday: "long", year: "numeric", month: "long", day: "numeric" })`.

```js
console.log(getGreeting(12), getGreeting(17), getGreeting(18)); // Good afternoon Good afternoon Good evening
console.log(getDateString(new Date(2026, 9, 16))); // Friday, October 16, 2026
```

**What you should see:** Nothing changes on the page. The console prints the three lines shown.

42. Create `readSetting(key)` and `saveSetting(key, value)`, which use `localStorage` but never throw an error.

**What to do:**

- `readSetting(key)`: **returns** `localStorage.getItem(key)`, or `null` if anything throws.
- `saveSetting(key, value)`: calls `localStorage.setItem(key, value)`, and quietly does nothing if anything throws.
- Wrap each one in `try` / `catch`.

**Check it in the console** (type these in the console and press Enter):

```js

console.log(readSetting("widget-test")); // hello
console.log(readSetting("never-saved")); // null
```

**What you should see:** Nothing changes on the page. The console prints `hello`, then `null`.

**Why it works:** Storage can be blocked (private browsing, some `file://` setups), and a thrown error must **never** break the shop. That's why the `try` / `catch` is here.

43. Create `setTheme(isDark)` and `toggleTheme()`, and restore the saved theme when the page loads.

**What to do:**

- Make a constant `THEME_KEY` with the text `"widget-shop-theme"`.
- `setTheme(isDark)`: uses `document.body.classList.toggle("dark-mode", isDark)` (the second argument forces it on or off), then saves `"dark"` or `"light"` under `THEME_KEY` with `saveSetting`.
- `toggleTheme()`: reads the current state **from the page** with `document.body.classList.contains("dark-mode")` (not from a separate variable) and calls `setTheme` with the opposite.
- Below the functions: if `readSetting(THEME_KEY)` is `"dark"`, call `setTheme(true)`.

> **Hint:** The BEGINNER track kept a separate `darkMode` boolean. What can go wrong when a boolean and the page disagree? (Here the page is the single source of truth.)

**Check it in the console** (type these in the console and press Enter):

```js
setTheme(true);
console.log(document.body.classList.contains("dark-mode")); // true
toggleTheme();
console.log(document.body.classList.contains("dark-mode")); // false
```

**What you should see:** When you run the first line, the page goes dark. `toggleTheme()` turns it back to light. Run `setTheme(true)` and reload the page: it stays dark. Run `setTheme(false)` before you go on.

45. Create a `keydown` listener on `document` that ignores modified keys and keys typed inside a box or menu.

**What to do:**

- Call `document.addEventListener("keydown", function (event) { ... })`.
- **Guard 1:** if `event.ctrlKey`, `event.metaKey`, or `event.altKey` is held, `return`. (Otherwise Ctrl+C, copy, would run the `c` shortcut.)
- **Guard 2:** if `event.target.tagName` is `"INPUT"`, `"SELECT"`, or `"TEXTAREA"`: when the key is `"Escape"`, call `event.target.blur()` to leave the box. Then `return`.
- Don't put anything else inside yet.

**What you should see:** Nothing visible yet. The console has no red errors.

46. Add to the `keydown` listener: number keys add a product by position, and every other key looks itself up in `shortcuts`.

**What to do:**

**Add this inside the listener**, below the two guards.
1. **Number keys.** `Number(event.key) - 1` is an index into `products`. If there is a product at that index, add one to the cart with `handleResult(state.cart.change(product.id, 1))` and `return`. A key like `"d"` or `"Enter"` gives `NaN`, and a position with no product gives `undefined`, so both do nothing.
2. **Everything else.** Look up `shortcuts[event.key]`. If there is one, call `event.preventDefault()` and **then** run it.

**The gotcha:** when the `c` shortcut calls `focus()` during `keydown`, the letter `c` is typed into the box. That's why `preventDefault()` comes first. Try it without, then with.

> **Hint:** `Number("d")` is `NaN`, and `NaN - 1` is `NaN`, and `products[NaN]` is `undefined`. So `if (product)` covers non-number keys. What about a space? `Number(" ") - 1` is `-1`, and `products[-1]` is also `undefined`.

**What you should see:** Click on the page (not in a box). Press `d`: the page goes dark, and stays dark after a reload. Press `c`: the coupon box is focused and **no `c` was typed** into it. Press `1` to `4`: products are added. Press `9`: nothing happens, with no error. Type `d` and `1` inside the Name box: nothing else happens. Ctrl+C or Cmd+C does not focus the coupon box.

**Check your work:**

## Part 6: Deal of the day and stats

*Suggested time: 4:00-4:45 (45 min)*

The finishing features. The deal of the day must be **the same for every customer all day** and different tomorrow, with no server and no stored data.

**You will build:** `getDayOfYear`, `pickDeal`, the banner, and a stats line above the order history.

**Key ideas:** `Date.UTC`, modulo to wrap around an array, a function with a default `date` parameter, changing an earlier function.

47. Create `getDayOfYear(date)`, which returns the day number in the year (January 1 is day 1).

**What to do:**

- Name: `getDayOfYear`. One parameter: `date`.
- Use `Date.UTC(...)` for both "today" (`date.getFullYear()`, `getMonth()`, `getDate()`) and "the day before January 1" (`Date.UTC(year, 0, 0)`), so daylight-saving changes can't shift the answer.
- **Return** `Math.round((today - dayBeforeJan1) / 86400000)`. (`86400000` is the milliseconds in a day.)

> **Hint:** `Date.UTC(year, monthIndex, day)` returns milliseconds. `Date.UTC(2026, 0, 0)` is the instant *before* January 1, so January 1 minus it is exactly one day.

**Check it in the console** (type these in the console and press Enter):

```js
console.log(getDayOfYear(new Date(2026, 0, 1)), getDayOfYear(new Date(2026, 1, 1))); // 1 32
console.log(getDayOfYear(new Date(2026, 9, 16)), getDayOfYear(new Date(2026, 11, 31))); // 289 365
```

**What you should see:** Nothing changes on the page. The console prints `1 32`, then `289 365`.

48. Create `pickDeal(date = new Date())`, which marks one product as the deal and returns it.

**What to do:**

- Name: `pickDeal`. One parameter: `date`, with a **default of `new Date()`**.
- The deal is `products[getDayOfYear(date) % products.length]`. The `%` (modulo) wraps the day number around the four products.
- Set `onDeal` to `true` for that product and to `false` for **every other** product, so there is never more than one deal. (`p.onDeal = p === deal` inside a `forEach` does it in one line.)
- **Return** the deal product.

**Check it in the console** (type these in the console and press Enter):

```js
console.log(pickDeal(new Date(2026, 9, 16)).name); // Gadget Pro
console.log(pickDeal(new Date(2026, 0, 2)).name); // Mini Gizmo
console.log(products.filter(function (p) { return p.onDeal; }).length); // 1
```

**What you should see:** Nothing changes on the page yet. The console prints `Gadget Pro`, `Mini Gizmo`, and `1`. (October 16 is day 289, and 289 % 4 is 1.)
