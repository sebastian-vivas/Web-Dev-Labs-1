This is the same shop as the BEGINNER track (project 99.01), but built the way a working developer would build it. The html page has **no products in it**. Your JavaScript renders everything from data. The html and css are all ready.

How the shop works:

- Products come from an array of objects made by a factory function
- All money is kept in whole **cents**, so there is no decimal drift
- A pricing engine of small functions works out bulk-quantity tiers, coupons with rules (minimum spend, weekends only), shipping, and tax
- The catalog, the cart, and the totals are drawn from one `state` object
- One click listener handles every button
- The checkout form shows **all** of its errors at once
- Orders are saved as snapshots, with a stats line
- Keyboard shortcuts, a saved theme, and a deal of the day that is the same for everyone all day

Four rules for this track:

1. **Data, then logic, then display.** Parts 1 and 2 never touch the page. You can test them entirely in the console.
2. **Money is whole numbers of cents.** `1999` means $19.99. Only `formatMoney()` turns cents into a string.
3. **Functions return; they don't reach out.** A function that works something out returns a value or a result like `{ ok: true, message: "..." }`. Only the render functions write to the page.
4. **One source of truth.** The `state` object is the only place the cart, the coupon, and the shipping choice live. The page is redrawn from it.

New in this track (not taught yet). Search "MDN" plus the name when you need one:

- `map`, `forEach`, `find`, `includes`, and `join` on arrays, and `Object.keys()`
- `event.target.dataset`, to read a `data-` attribute
- default parameter values, like `function f(date = new Date())`
- `Number.isInteger()`, `trim()`, `padStart()`, and `replace()`
- `toLocaleDateString()`
- `localStorage` inside `try` / `catch`
- the `submit` event on a form

14. Add a `change(id, delta)` method to the cart that adds `delta` to a product's quantity, and returns a `{ ok, message }` result object.

**Add this to `createCart`**, below `getQty`. Name: `change`. Two parameters: `id` and `delta` (a positive number adds, a negative number removes).

It **returns** a result object `{ ok: boolean, message: string }`. Work through these rules **in this order**, with early `return`s:

1. No product has that id (`findProduct(id)` is `undefined`): `{ ok: false, message: "Unknown product." }`
2. `delta` is not a whole number (`Number.isInteger(delta)` is `false`): `{ ok: false, message: "Quantity must be a whole number." }`
3. Work out `wanted`: the current quantity plus `delta`.
4. `wanted` is more than the product's `stock`: `{ ok: false, message: "Only 5 Wonder Widget in stock (you have 3 in your cart)." }` (use the real stock, name, and current quantity)
5. `wanted` is 0 or less: remove the id from `items` with `delete`, and return `{ ok: true, message: "Removed Wonder Widget." }`
6. Otherwise, store `wanted` in `items`, and return `{ ok: true, message: "Wonder Widget × 3 in cart." }` (use the name and the new quantity)

**A failed call must not change the cart.**

Returning `{ ok, message }` (instead of throwing errors or writing to the page) lets any caller decide what to do with the result. The page code later shows the message. Other code can just check `ok`.

Test it in the console:

```js
var c = createCart();
console.log(c.change("widget", 3)); // { ok: true, message: "Wonder Widget × 3 in cart." }
console.log(c.change("widget", 5)); // { ok: false, message: "Only 5 Wonder Widget in stock (you have 3 in your cart)." }
console.log(c.change("widget", 1.5).ok, c.change("nope", 1).ok); // false false
console.log(c.getQty("widget")); // 3
console.log(c.change("widget", -3).message, c.getQty("widget")); // Removed Wonder Widget. 0
```

Save and reload. Nothing changes on the page. The console prints the five lines shown. The failed calls leave the quantity at `3`.

16. Create `validateCoupon(code, subtotal, date = new Date())`, which returns `{ ok, pct, message }` for a coupon code.

31. Create `escapeHTML(text)`, which makes user-typed text safe to put into `innerHTML`.

```js
function escapeHTML(text) {
  return text
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g, "&quot;");
}
```

Anything the customer types (their name!) can contain HTML. If you put `<img src=x onerror=alert(1)>` into `innerHTML` unescaped, it **runs**. This is called an XSS (cross-site scripting) attack. Turning those four characters into harmless text stops it.

Test it in the console:

```js

console.log(escapeHTML('a & "b"')); // a &amp; &quot;b&quot;
```
